# /flow-map
대상: `$ARGUMENTS` (ex: `결제`, `all`). 비어 있으면 `all`이다.
결과물: `.claude/docs/flows/ui-flows.md`. TC-Writer가 TC 스텝과 사전 조건을 이 지도와 대조한다. 테스트 코드나 TC는 고치지 않는다.

## 1. 원칙
- 실제로 화면에서 확인한 것만 쓴다. 스펙이나 기억으로 채우지 않고, 확인한 날짜를 섹션마다 적는다.
- 데모 사이트 결제 확정은 흐름 확인에 필요하면 한다(2026-10-10 사용자 허용). 결제 방법은 Cash on Delivery처럼 외부 입력이 없는 것을 쓴다.
- 로그인 실패 반복(계정 잠금) 같은 되돌릴 수 없는 동작은 하지 않는다. 그 직전 화면까지만 확인하고 "이후는 미확인"으로 적는다.
- 계정은 UI 테스트 계정(customer2, `.env`)만 쓰고 값은 쓰지 않는다.
- Playwright MCP는 `browser_snapshot`을 기본으로 쓰고, 스크린샷은 흐름이 갈라지는 곳에서만 남긴다(토큰 절약).

## 2. 흐름 지도 형식
화면(페이지)마다 한 섹션이다.
```
## <화면 이름> (URL 경로)  — 확인 YYYY-MM-DD
- 진입 경로: 어디서 무엇을 눌러 오는지 (여러 개면 모두)
- 상태 조건: 이 화면이 어떻게 달라지는지 (ex: 로그인 여부, 장바구니 비어 있음, 품절 상품)
- 주요 요소: 실제 UI 표기 그대로 (버튼 [Proceed to checkout], 필드 [Email address], 문구 "...")
- 다음 화면: 요소 → 이동하는 화면
- 분기: 상태에 따라 단계가 생략되거나 달라지는 곳 (ex: 로그인 상태면 Sign in 단계에서 바로 [Proceed])
- 미확인: 확인하지 못한 것과 이유
```
- 맨 위에 화면 목록과 핵심 흐름(메인 → 상품 상세 → 장바구니 → Sign in → Billing Address → Payment) 요약을 둔다.

## 3. 절차
1. 기존 지도가 있으면 읽고, 대상 범위의 섹션만 다시 확인한다. 바뀐 곳은 고치고 확인 날짜를 갱신한다.
2. 비로그인과 로그인 두 상태로 대상 흐름을 따라간다. 장바구니는 비어 있을 때와 상품이 있을 때를 모두 본다.
3. 지도를 쓰고, 이전과 달라진 점을 보고에 적는다.
4. 결과 보고: 갱신한 화면, 새로 발견한 분기, TC 스텝과 맞지 않아 보이는 TC ID(후보), 미확인 항목

## 4. 다음 단계
- 맞지 않아 보이는 TC가 있으면 `/tc-write`로 정비를 맡긴다(TC-Writer가 지도와 대조해 고친다).
