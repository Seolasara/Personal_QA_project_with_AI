# 백로그 항목 작성 형식
대상: `.claude/docs/backlog/` 아래 상태별 파일. 새 항목은 `test-triage`로 분류하고 스펙과 라이브를 비교한 뒤 쓴다. 스펙 불일치 목록도 이 백로그가 대신한다.

## 1. 구조
항목 하나가 `###` 섹션 하나다. 위에서 아래로 항목 설명, 대상 TC 순서다.
```
### #번호 문제 요약
- 문제 정의: (스펙과 무관한 항목만. TC 없이 설명할 때 쓴다)
- 발생 배경: 어떤 작업 중 어떻게 발견했는지
- 추정 원인과 근거: 원인 추정과 근거(소스, 스펙, 라이브 확인)
- 분류와 상태: 분류(유형) / 중요도 / 상태 / 발견 날짜, 마지막 확인 날짜
- 대상 TC
  1. [TC 번호] 시트의 TC 제목
     - 스펙: 스펙이 정의한 값(상태 코드, 스키마, 문구)과 위치(`api-docs.json`, `v5` AC 번호)
     - 라이브: 실제 동작(요청과 응답 값). 비교 대상이 있으면 함께 쓴다.
     - 현재 테스트: (선택) 지금 테스트가 어떻게 통과하거나 pin되어 있는지
  2. [TC 번호] 시트의 TC 제목
```
- 제목: `### #번호 문제 요약`. 요약은 현상 한 줄로 짧게 쓴다. TC 번호와 날짜는 제목에 쓰지 않는다.
  - 번호: 가장 큰 번호 다음 번호. 한번 쓴 번호는 xfail 사유와 Jira 이슈가 참조하므로 바꾸지 않는다.
  - ex: `### #13 존재하지 않는 상품의 연관 상품 조회가 500`
- 대상 TC: 번호를 붙여 TC마다 한 항목으로 쓴다.
  - `[TC 번호]`는 시트 ID, 뒤에는 시트의 TC 제목(시나리오)을 그대로 쓴다. TC가 없으면 `[TC 없음]` 뒤에 대상 기능을 쓴다.
  - 여러 TC가 같은 스펙과 라이브를 공유하면, 그 TC들을 연속으로 쓰고 마지막 TC 아래에 스펙, 라이브를 한 번만 쓴다.
  - 스펙 불일치가 아닌 항목(기술부채, env 등)은 "대상 TC"를 생략하거나 TC만 나열한다.
- "분류와 상태"
  - 분류: `test-triage` 6분류 또는 안건, 운영 메모, 기술부채, 판단 보류. 스펙과 비교한 항목은 "스펙 불일치" 또는 "스펙 미정의"를 괄호로 적는다.
  - 중요도: High/Medium/Low. 기준은 `.claude/guides/issue-severity.md`. 결함이 아닌 항목(기술부채, 운영 메모)은 생략한다.
  - 상태: Jira 키, xfail 처리 여부, 사용자 결정, 간헐 결함이면 재현성과 "회귀 대상"

## 2. 쓰기 전 확인
- 인덱스(`00_index.md`)에서 같은 원인의 항목이 있는지 찾는다. 있으면 새 번호를 만들지 않고 그 항목의 대상 TC에 추가한다.
- 라이브 값은 바뀔 수 있으므로 쓸 때 날짜를 함께 적는다.

## 3. 스펙과 라이브 비교 분류 (2026-10-10 재정리)
판단 기준은 "스펙이 기대결과를 정해 두었는가"다.
1. 스펙 불일치 = real-bug (`01_real-bug.md`)
   - 스펙이 상태 코드, 응답 스키마, 메시지·문구, 값(예시값 포함)을 정했는데 라이브가 다르다.
   - 노션 "이슈 검수" 후보 → Jira. 결과 보고서에서는 Fail이다.
2. 스펙 미정의 = 안건 (`02_agenda.md`)
   - 스펙이 그 동작이나 응답을 정하지 않아 정확한 기대결과가 없다. 제약은 있지만 위반 시 응답이 없는 경우도 여기다.
   - TC에 `spec_undefined` 마커를 붙여 전체 실행에서 빼고, 결과 보고서에는 N/A로 쓴다. wiki 안건 문서로 올린다.
   - 예외: 스펙에 기준이 없어도 기능 의도상 기대결과가 분명하면 사용자 판단으로 real-bug가 될 수 있다(ex: #26).
3. 시트 오기: 라이브가 스펙과 같고 TC 값이 틀렸다. 백로그가 아니라 TC 수정 대상이다.
- 확인 순서: 스펙(`api-docs.json`) → Swagger → wiki "API specification"(Confluence 6750210) → TC. UI는 `v5` 분석 파일(`.claude/docs/spec analysis/ui/`)을 따른다.
- 스펙 비교가 아닌 항목(테스트 코드, 환경, 운영)은 `03_tech-debt-env.md`, 분류를 못 정한 것은 `04_hold.md`다.

## 4. 파일 배치와 이동
- `01_real-bug.md`: Jira로 올릴 결함
- `02_agenda.md`: 스펙 쪽 판단이 필요한 불일치(wiki 안건 문서로 올림)
- `03_tech-debt-env.md`: 테스트 코드, 설정, 환경, 운영 메모
- `04_hold.md`: 확인 중이라 분류를 정하지 못한 것
- `05_done.md`: 해결되었거나 폐기된 것. 완료되면 여기로 옮기고 상태를 적는다. 지우지 않는다.
- 항목을 쓰거나 옮기면 `00_index.md`의 목록과 "다음 번호"도 함께 고친다.
