# 이슈 중요도 기준
대상: 백로그 항목, Jira 이슈, 결과 보고서. 셋이 같은 값을 쓴다. wiki QA plan(UI 65702, API 5996545)의 리스크 판정 축을 발견된 결함에 적용한 것이다.

## 1. 등급 (3단계)
- High: 핵심 흐름(로그인 → 상품 조회 → 장바구니 → 결제)이 우회 경로 없이 막히거나, 금전·데이터가 훼손되거나 되돌리기 어려운 상태 변화가 생긴다.
- Medium: 중요 기능이 부분적으로 실패하지만 우회 경로가 있다.
- Low: 비핵심 기능이거나 사용 흐름에 영향이 거의 없다(문구, 시각 요소, 보조 기능).

## 2. 판정 방법
1. 결함이 실제로 일으키는 영향으로 판정한다. 발생한 기능의 TC 중요도는 출발점일 뿐 그대로 따르지 않는다.
   - ex: High 기능(장바구니)에서 문구만 스펙과 다르면 Low
2. QA plan의 축3(스펙 불일치는 한 단계 상향)은 이슈 중요도에 적용하지 않는다. 축3은 테스트 우선순위를 정하는 사전 기준이라, 이미 발견된 결함에 다시 적용하면 이중으로 반영된다.
3. 간헐적으로 재현되는 결함도 등급을 내리지 않는다.
   - 백로그 "분류와 상태"에 재현성(ex: 간헐 1/3회)과 확인 날짜를 적고 추적한다.
   - 관련 TC는 상태에 "회귀 대상"으로 표시해 전체 실행 때마다 결과를 본다.
   - 간헐 결함은 `xfail(strict=True)`로 고정하지 않는다. 통과할 때 XPASS로 실패가 나서 신호가 흐려진다.
   - 서버가 응답하지 못한 실패(타임아웃, 5xx, DB 리셋)는 결함이 아니라 env다. 같은 조건에서 앱 동작이 달라질 때만 간헐 결함으로 본다.
4. 판단이 서지 않으면 '추정'으로 적고 결과 보고의 `ask_user`에 올린다.

## 3. 쓰는 곳
- 백로그: "분류와 상태"의 `중요도 High|Medium|Low`
- Jira: 우선순위 필드와 본문 Severity
- 결과 보고서: 이슈 목록의 중요도 열. QA plan 사인오프의 "미해결 High 결함 0건" 판정에 쓴다.
